# Cycle 05: Accuracy vs Speed Orchestration Engine - UAT

## Test Scenarios
The primary user acceptance testing scenarios focus specifically on proving the absolute robustness and flawless mathematical translation of the visual accuracy slider generated by the React Flow/Three.js frontend and its precise integration seamlessly into the highly specific, text-based active learning thresholds natively required by the core engine. The UAT simulates the safe mathematical processing of a simplified spatial GUI representation perfectly. This cycle proves that a single intuitive control can govern complex AI logic without exposing the user to the danger of unphysical configurations or infinite loops.

* **SCENARIO-05-A [Priority: High] - Successful Heuristics Translation (Speed Priority):** The UAT must simulate a user completing the simplified configuration, prioritizing speed. The interface successfully receives a valid Intent payload (e.g., Accuracy Slider: 2) into the backend. The API explicitly correctly streams the entire configuration accurately into the highly precise nested schema natively required. The resulting configuration must reflect high tolerance for uncertainty and sparse active learning checks. The simulated user intends to rapidly explore a large phase space of a solid-state material to identify general structural trends, accepting that the resulting MLIP might lack the precision required for exact phonon calculations. They drag the visual slider down to a value of '2'. The frontend transmits this single integer. The Semantic Compiler invokes the Heuristics Engine. The engine calculates a large `candidate_threshold` (e.g., 0.15 eV/atom) and sets the `check_interval` to evaluate MACE uncertainty only once every 20 MD steps. It also maximizes the integration timestep to 2.0 fs to accelerate the physical time covered per wall-clock hour. The test will verify that the final compiled `WorkflowConfig` reflects these aggressive parameters, proving that the user successfully configured a high-speed, exploratory simulation with a single click. This scenario demonstrates the system's ability to maximize computational throughput when requested. Furthermore, the test will explicitly verify that even at this extreme "speed" setting, the heuristic engine clamps critical stability parameters; for example, it asserts that the barostat damping parameter does not drop below a critical threshold (e.g., 100.0 fs) that would cause the simulation box to fluctuate violently and crash the LAMMPS engine, proving that "speed" does not mean "unsafe".

* **SCENARIO-05-B [Priority: High] - Accurate Mathematical Slider Evaluation (Accuracy Priority):** The UAT tests that complex internal mathematical logic correctly populates the correct intelligent threshold values when prioritizing accuracy. An Intent payload with an Accuracy Slider of 9 must generate a `WorkflowConfig` with an extremely low `candidate_threshold`, forcing the simulation to frequently halt and request high-fidelity DFT validation from Quantum ESPRESSO. In this scenario, the user is preparing a production-quality MLIP intended for calculating highly sensitive thermodynamic properties like surface energies, transition states, or defect formation energies. They require absolute confidence in the MACE predictions and cannot tolerate extrapolation. They drag the visual slider to '9'. The frontend transmits this integer. The Heuristics Engine receives this value and employs its non-linear scaling functions. It calculates a minuscule `candidate_threshold` (e.g., 0.01 eV/atom), drops the integration timestep to a highly conservative 0.5 fs, and sets the `check_interval` to evaluate the uncertainty at every single MD step. Furthermore, it automatically adjusts the Quantum ESPRESSO `ecutwfc` (kinetic energy cutoff) to a very high, rigorous value (e.g., 80 Ry) to ensure the training data itself is as precise as possible. The test suite will meticulously assert that the final `WorkflowConfig` contains these highly restrictive parameters. This proves that the system successfully interpreted the user's desire for rigorous accuracy and translated it into a configuration that will aggressively invoke the DFT oracle at the slightest hint of uncertainty, prioritizing scientific correctness over simulation speed. The test will also verify that the non-linear scaling curve correctly amplified the strictness of these parameters compared to a slider value of 5, ensuring the difference between "balanced" and "accurate" is physically meaningful.

* **SCENARIO-05-C [Priority: Medium] - Preservation of Manual Overrides (Expert Mode):** The UAT will verify that if an advanced user explicitly provides a specific threshold parameter (e.g., manually setting `threshold_call_dft` in the advanced settings panel) alongside the visual slider, the explicit manual override takes precedence over the heuristically generated default, ensuring flexibility for power users. The simulated user is an expert computational chemist. They appreciate the convenience of the 'Accuracy vs. Speed' slider for setting general parameters (like the MD timestep, the thermostat settings, and the MACE training epochs), but they have specific, published requirements for the DFT convergence criteria for their specific material system. They set the visual slider to '5' (Balanced). However, in the GUI's "Advanced Settings" panel, they manually override the `ecutwfc` parameter for Quantum ESPRESSO, setting it to 60 Ry instead of the heuristic default of 40 Ry, and they manually specify a very particular `learning_rate` for the Pacemaker module. The frontend transmits a payload containing both the slider value and the explicit overrides. The Semantic Compiler first requests the full suite of default parameters for a slider value of 5 from the Heuristics Engine. Then, it explicitly applies the user's manual overrides, overwriting the `ecutwfc` and `learning_rate` values in the generated dictionary. The test will assert that the final `WorkflowConfig` contains the heuristic defaults for all unmentioned parameters, but contains the user's explicit value of 60 Ry for `ecutwfc` and the specific `learning_rate`. This scenario proves that the Intent-Driven GUI remains a powerful tool for experts, offering extreme abstraction without sacrificing absolute granular control when necessary. Furthermore, the UAT will test a scenario where an expert override violates an absolute safety bound (e.g., setting the timestep to -1.0 fs or the `ecutwfc` to 0). The test will verify that the system correctly catches this tier-1 violation and returns a 422 error, proving that even explicit overrides cannot force the system into a impossible state.
