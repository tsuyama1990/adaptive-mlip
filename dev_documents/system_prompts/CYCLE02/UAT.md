# Cycle 02: Semantic Compiler and Config Translation - UAT

## Test Scenarios
The primary user acceptance testing scenarios focus specifically on proving the absolute robustness and flawless mathematical translation of the Semantic Compiler layer, bridging the frontend GUI representations into the deeply nested `WorkflowConfig` payload without triggering execution loops. The UAT simulates the successful processing of a simplified React Flow DAG. This cycle proves that the "brain" of the visual interface can accurately interpret human intent and generate complex machine instructions reliably, transforming a simple collection of connected shapes into a rigorous representation of a complete scientific experiment.

* **SCENARIO-02-A [Priority: High] - Successful DAG to WorkflowConfig Translation:** The UAT must simulate a user completing the simplified configuration. The interface successfully injects a fully valid JSON payload containing a DAG (e.g., Initial Structure -> Fine-Tuning -> Active Learning) specifically into the REST API. The API explicitly correctly compiles the entire configuration accurately into the highly precise nested schema natively required. This verifies the core value proposition of the visual workflow editor. In this scenario, the simulated user has placed three nodes on the canvas. The first is an `INITIAL_STRUCTURE` node containing the string "Al" and a lattice parameter. The second is a `MACE_TRAINING` node indicating the model should be fine-tuned on an existing dataset. The third is the `ACTIVE_LEARNING_LOOP` node. The user connects these nodes sequentially with directed edges. When the simulated frontend submits this payload via a `POST` request to the `/api/v1/intent/compile` endpoint, the Semantic Compiler must parse the JSON, validate the topology of the DAG, recognize the sequence of operations, and construct the deeply nested `LoopStrategy` list required by the PyAceMaker orchestrator. The API must return a 200 OK status containing the full `WorkflowConfig` JSON. The test will verify that the resulting configuration correctly configures the LAMMPS driver with an EAM potential for Aluminium, sets up the Pacemaker training configuration for the MACE fine-tuning step, and correctly configures the Two-Tier Evaluator with intelligent defaults for the active learning loop, proving the compiler successfully translated the visual intent into a complete, executable physical simulation. The test suite will recursively examine the output JSON object, asserting that specific keys (e.g., `config.driver.lammps_command_template`) contain the exact strings expected for this specific workflow, ensuring the translation logic is deterministically correct and free from unexpected side effects or omitted configurations that would later cause the orchestrator to crash during execution.

* **SCENARIO-02-B [Priority: High] - Intelligent Default Parameter Injection:** The UAT tests that complex internal configurations unprovided by the non-expert engineer (e.g., `soft_start_steps`, `candidate_threshold`) are flawlessly populated with correct intelligent default physics parameters correctly. This ensures the simulation will not crash due to missing, highly esoteric parameters that the user should not have to care about. The user constructs a minimal DAG consisting only of an `INITIAL_STRUCTURE` node and an `ACTIVE_LEARNING_LOOP` node, deliberately omitting any advanced hyperparameter tuning. They submit the payload. The Semantic Compiler receives the payload and recognizes that crucial parameters required by the active learning orchestrator—such as the molecular dynamics time step, the Langevin thermostat damping parameter, the frequency of DFT uncertainty evaluations, and the specific convergence criteria for the Quantum ESPRESSO backend—are missing from the input intent. The compiler must intelligently inject safe, physically sound defaults for all of these parameters based on the context of the simulation (e.g., inferring the atomic mass of the elements present in the initial structure to set appropriate dynamics parameters). The API returns the compiled `WorkflowConfig`. The test suite will meticulously inspect this resulting configuration object, asserting that every single required nested field (e.g., `config.active_learning.evaluator.soft_start_steps`, `config.dft_driver.ecutwfc`) is present and populated with a physically valid value, proving that the system successfully shielded the user from the mechanical complexity of the underlying simulation engines. Furthermore, the test will explicitly verify that these injected defaults are not hardcoded randomly, but are derived or sourced from established lookup tables (e.g., ensuring a lighter element like Hydrogen results in a smaller default MD timestep compared to a heavier element like Tungsten, thereby preventing integration instability), demonstrating the true intelligence of the compiler's injection strategy.

* **SCENARIO-02-C [Priority: Medium] - Logical Workflow Validation Rejection:** The UAT will attempt to compile a sequence of nodes that is logically invalid in a physical sense, such as placing an active learning loop before any initial structure has been loaded. The compiler must reject this and return a human-readable error explaining the logical contradiction, demonstrating that the system actively prevents meaningless simulations. The simulated user incorrectly draws a directed edge from an `ACTIVE_LEARNING_LOOP` node to an `INITIAL_STRUCTURE` node, creating a physically impossible sequence where the system attempts to run molecular dynamics before defining the atoms to simulate. The user submits this flawed payload to the compilation endpoint. The Semantic Compiler's topological sorting algorithm and logical validation sequence must detect this contradiction immediately. It must halt compilation and raise a `CompilerError`. The API gateway must catch this exception and return a 400 Bad Request status code. The JSON response body must contain a clear, user-friendly error message indicating the specific logical flaw—for example, "An INITIAL_STRUCTURE node must precede any execution nodes in the workflow sequence." The React frontend will receive this error and display a warning to the user, preventing them from attempting to run a doomed simulation and proving the robustness of the Semantic Compiler's validation logic. We will also test a scenario involving an unsupported branching topology. The user constructs a DAG where an `INITIAL_STRUCTURE` branches into two parallel `ACTIVE_LEARNING_LOOP` nodes simultaneously. The Semantic Compiler detects this unsupported parallel execution intent, halts the compilation, and immediately returns a 400 Bad Request detailing that "Parallel active learning loops originating from a single structure are currently not supported by the orchestrator," proving the compiler correctly acts as a gatekeeper against topologies the backend state machine cannot physically execute, thereby preserving system stability.
