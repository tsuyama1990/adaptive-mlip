# PyAceMaker Master User Test Scenarios & Tutorial Plan

## Tutorial Strategy
The tutorial strategy for the new PyAceMaker Intent-Driven GUI framework is designed to eliminate the traditionally steep learning curve associated with molecular dynamics active learning configurations. We will accomplish this by translating all user acceptance testing (UAT) scenarios into exactly one highly robust, interactive Marimo notebook.

This single file approach ensures that new non-expert engineers and users experience a guided, logically sequential step-by-step introduction. The tutorial will run in precisely two strictly controlled execution modes, providing flexibility for both initial exploration and final production validation. This ensures the user gains confidence in the visual interface before committing extensive cloud computing resources.

1.  **Mock Mode (CI & Exploration):** The default mode. In this mode, the system utilizes precise mock computational drivers (e.g., `DummyLammpsModule`, `DummyMaceOracle`), effectively bypassing all actual computationally heavy DFT calls. This permits rapid, secure exploration by users, allowing them to experiment with complex DAG structures and the Accuracy vs. Speed slider instantly. They can observe the real-time telemetry updates and preflight validation checks without waiting hours for a single simulation step to complete. This is critical for an engaging, interactive tutorial experience where the feedback loop must be measured in milliseconds, not hours.
2.  **Real Mode (Production Validation):** When executed with valid API keys or specific physical execution environments, the notebook seamlessly switches to running actual computationally expensive calculations. This mode serves as the ultimate proof that the Intent-Driven GUI correctly translates visual abstractions into real-world physical simulations. The tutorial will guide the user through a minimal, fast-converging system (like a small Aluminium unit cell) to prove the end-to-end functionality without consuming excessive time.

## Tutorial Plan
The execution of the user tutorials will be centralized purely into a **SINGLE** Marimo Text/Python file named: `tutorials/UAT_AND_TUTORIAL.py`.

This single Marimo notebook will contain all specific User Test Scenarios derived from all 6 development cycles cleanly and correctly. The notebook will be structured logically to mirror the user's intended workflow, starting from the simplest abstractions and gradually introducing more powerful visual features.

*   **Section 1: The Intent-Driven API Basics (Cycle 01 & 02):** The tutorial will initially visually guide the non-expert user safely through the process of constructing simple DAG representations visually, without manually providing specific thresholds. It will demonstrate how the Semantic Compiler injects intelligent default physics parameters, proving that a complex active learning loop can be initiated with merely a few clicks and a dataset selection.
*   **Section 2: Interactive Spatial Tagging (Cycle 03):** The notebook will clearly feature interactive UI components, allowing the user to securely and accurately map spatial boundaries visually. The tutorial will display a 3D rendering of a metallic slab and instruct the user to "paint" the bottom layer. It will then demonstrate how the backend seamlessly translates this visual painting into the correct LAMMPS `freeze_group` commands, preventing unphysical structural collapse during the MD simulation.
*   **Section 3: Real-Time Telemetry Visualization (Cycle 04):** A dedicated section will dynamically visually stream pseudo-trajectory data. The user will watch as the MACE oracle evaluates the incoming atomic configurations, with high-uncertainty atoms lighting up in red on the 3D viewer. This section proves that the asynchronous WebSockets and Pub/Sub telemetry architecture functions robustly under load, providing crucial transparency to the AI's decision-making process.
*   **Section 4: The Accuracy vs Speed Trade-off (Cycle 05 & 06):** The concluding section will allow users to securely manipulate the 1-10 slider and observe the automatically generated preflight diagnostics. The user will be instructed to drag the slider to 'Speed' and observe the resulting sparse sampling rate, then drag it to 'Accuracy' and observe the highly sensitive `candidate_threshold`. Finally, they will intentionally introduce a structural error to witness the Preflight Diagnostics immediately halt the simulation, proving the system's fail-safe design.

## Tutorial Validation
Validation of the entire tutorial strategy relies purely upon the automated execution of the `tutorials/UAT_AND_TUTORIAL.py` file. We will use `uv run python tutorials/UAT_AND_TUTORIAL.py` securely within the CI pipeline.

The CI environment will run purely in the explicit Mock Mode, verifying that all cells execute sequentially without raising exceptions. This guarantees that the tutorial remains functional as the underlying codebase evolves, preventing the common issue of outdated, broken documentation. By treating the tutorial as an executable test suite, we ensure that the user experience is mathematically verified alongside the core physical logic of PyAceMaker.
